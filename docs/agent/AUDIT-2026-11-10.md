# PrivacyFold — Pre-Deployment Audit

**Date:** 2026-11-10 · **Auditor:** Hermes (read-only audit + probe builds) · **Scope:** everything under `~/Projects/privacyfold`
**Question asked:** "Are we completely ready for production deployment?"
**Answer:** **No. Not deployable today.** The design is production-grade; the engineering is a demo shell. Three independent hard failures block the build, and a measurable share of the "live" tools return fabricated output.

Every claim below is backed by a command, a file:line, or a probe run recorded in this document. Where I could not verify something, it says so.

## 1. Build: fails, twice, for two unrelated reasons

Install is clean:

```
$ npm install --no-audit --no-fund
added 181 packages in 43s          # node v26.0.0, npm 11.12.1
```

Build is not:

```
$ npm run build
✓ Git-CMS Validated: 72 tools, 87 presets, 6 blog guides.
▲ Next.js 15.5.29
Failed to compile.
./src/app/tools/[slug]/for/[presetSlug]/page.tsx
Module not found: Can't resolve '@/lib/cms'
BUILD_EXIT=1
```

**Failure 1 — `src/app/tools/[slug]/for/[presetSlug]/page.tsx`** imports `@/lib/cms`, which does not exist (the loader is `@/lib/git-cms`). The file is dead scaffolding from an earlier content model (`preset.authority_name`, `tool.Engine`). It also declares `/tools/[slug]` beside `/tools/[toolSlug]`, which Next rejects as *"You cannot use different slug names for the same dynamic path"* — the module error just fires first.

**Failure 2 — the content model does not match the code.** Removing the dead route (probe in a scratch copy, repo untouched) compiles, then dies at prerender:

```
✓ Compiled successfully in 4.5s
Generating static pages (0/172) ...
TypeError: Cannot read properties of undefined (reading 'toLowerCase')
Export encountered an error on /tools/[toolSlug]/[presetSlug]/page: /tools/jwt-decode/...
Export encountered an error on /tools/ada-pdf
```

Cause, measured across all 72 content files:

| Field the code requires (`GitCmsTool`) | Present in `content/tools/*.json` |
|---|---|
| `fam`, `task`, `glyph`, `desc`, `accepts`, `tag`, `wasmModule`, `std` | **0 / 72** |
| `seo.steps` (rendered as `tool.seo.steps.map(...)`) | **0 / 72** |
| `seo.faqs` | 72 / 72 |

The JSONs use `category/description/Engine/badge/size`; the loader and `schema-generator.ts` expect `fam/desc/wasmModule/task/std/seo.steps`. `tool.task.toLowerCase()` on `undefined` is the crash. Fixing it is not a one-line patch — it is a content migration across 72 files plus the TS interface.

**Consequence:** `npm run build` produces **0 usable pages**. The only artifact that currently renders the product is `privacyfold-nextjs/dist/index.html` (438,854 B), a hand-maintained standalone file that **no script in the repo regenerates**. If it is lost or diverges, there is no path back.

## 2. The Next.js app and the runtime were never connected

`src/components/PrivacyFoldApp.tsx` (26 lines) is the entire interactive product surface:

```tsx
return <div id="pf-root-shell" dangerouslySetInnerHTML={{ __html: "" }} />;
```

It injects `/app-runtime.js` (336,853 B, 4,478 lines) into an **empty div**. That runtime expects the full desk markup — `#grid`, `#home`, `#toast`, `#stage`, `#tpName`, `#cmsIn` — which exists only inside `dist/index.html` / `index.html`.

Probe: a minimal page with exactly the shell the component renders, plus the real runtime.

```json
{"root": 0, "text": "", "pf": "undefined"}
```

Blank page. `window.privacyfold` is never defined, so even the advertised SDK is absent on every Next route.

So there are two products in the tree: a **vanilla-JS single file** that works (`dist/index.html`), and a **Next.js port that renders nothing**. `index.html` and `reference-ui.html` at the repo root are byte-identical (sha256 `516a47eb…`) — the static design reference, correctly kept out of the build.

## 3. "WebAssembly / WebGPU / on-device AI" is not implemented

```
$ find . -name "*.wasm" -not -path "*/node_modules/*"
(no results)
```

Yet the same directory advertises WASM in every customer-facing surface:

| Surface | Claim |
|---|---|
| `public/llms.txt` | `[Tier: D \| Engine: /wasm/photo/passport-photo-v1.wasm]` × 72 tools |
| `public/schemas/_index.json` | `"engine": "/wasm/...-v1.wasm"` × 72 |
| `public/.well-known/mcp.json` | `"engine": "@jsquash/jpeg + …", "libheif-wasm", "FFmpeg.wasm", "Whisper-Tiny ONNX"` |
| `ToolSeoArticle.tsx:49` | renders `{tool.wasmModule} (In-Browser RAM)` on every tool page |
| `schema-generator.ts:21` | `featureList: ["Powered by …"]`, `"Works offline via Progressive Web App Service Worker"` |
| `content/config/wasm-sri.json` | SHA-256 of `""` and of `"abc"` for `mozjpeg_enc.wasm` etc. |

There is no `fetch` of any `.wasm` in `app-runtime.js`, no `import()` of any bundled library, and **every declared dependency is imported zero times**:

```
@huggingface/transformers 0 · @jsquash/{avif,jpeg,png,webp} 0 · pdf-lib 0
tesseract.js 0 · sql.js 0 · openpgp 0 · lucide-react 0 · clsx 0 · tailwind-merge 0
```

The heavy dependencies are decoration in `package.json`. Some tools genuinely work — `passport_photo` (canvas crop), `image_compress` (canvas encode), `exif_strip` (re-encode strips APP1), `hash_gen` (WebCrypto), `json/base64/jwt/uuid/regex/csv/url/text-diff/unit/cron/ua/password/qr/color-contrast`. Those are real. The WASM/AI tier is not.

## 4. Some "live" tools fabricate user data (the most serious finding)

Reproduced live against `dist/index.html` via the shipped SDK:

```js
await window.privacyfold.run('pdf_compress', {preset:'uk-visa-vfs', gray:false},
  'MY REAL PASSPORT SCAN TEXT WITH NRIC 123456789')
```

Returns a **431-byte PDF** whose only content is a printed line:

```
BT /F1 11 Tf 50 740 Td (Compressed for preset: uk-visa-vfs | Grayscale: false) Tj
```

A user who uploads a 4 MB scanned passport and downloads this has **lost their document**. `pdf_compress` is `live:true`, is the target of 7 SEO preset pages, and the code path (`app-runtime.js:3527`) never parses a PDF.

```js
await window.privacyfold.run('ocr_scan', {target:'w9'},
  'Invoice INV-2024-88 dated 3 March 2024 total GBP 1,250.00')
```

Returns:

```
[Source Crop #1] Legal Name (Line 1):    Acme Global Ltd.
[Source Crop #3] Reported Gross Amount:  $6,050.00
```

The source document contains **neither** string. `Acme Global Ltd.` is a literal in the code; the amount falls back to `['$6,050.00']` when the regex finds nothing; the date falls back to `['2026-11-10']`. This is a W-9/SA100 pre-fill tool: fabricated legal name and amount in a tax form is the worst failure mode the product can have.

Also in the same class:

- `voice_transcribe` — with no input, "transcribes" a hardcoded sentence about Moonshine-tiny.
- `bg_remove` — flood-fill colour distance; labelled `BEN v2 / MODNET via ONNX Runtime WebGPU (~120ms)`.
- `chat_pdf` — keyword scoring; labelled `bge-micro embeddings + pdfjs-dist`.
- `ai_writer` — rule-based rewriting; labelled `window.ai + SmolLM2-135M`.

Additionally, `exposure_xray`, `hash_gen`, `exif_strip` etc. are honest. The product's trust proposition is exactly the thing being faked.

**Eight tools are sold but do not exist at all** (they are `live:false` in the runtime, yet each has a full SEO page, a JSON-LD `SoftwareApplication`, a schema, and an entry in `llms.txt`): `pdf-merge`, `pdf-split`, `pdf-redact`, `w9-prep`, `sa100-prep`, `heic-to-jpg`, `signature-clean`, `file-encrypt`. These are the highest-commercial-intent tools in the catalog. Every one surfaces "Coming soon" *inside* the workspace while the surrounding page promises it works.

## 5. Agent surface: advertises tools that don't exist, fakes its own signature

`public/.well-known/mcp.json` lists **40** tools; three have no implementation anywhere (`media-trim`, `paper-plane`, `voice-notes`). The registry contradicts itself in four places:

| File | Count |
|---|---|
| `src/app/layout.tsx`, `content/config/site.json`, `README.md` | **40** |
| `packages/mcp-server/index.mjs` (`list-tools` → `total_tools`) | **42** |
| `public/llms.txt`, `public/schemas/_index.json` | **72** |
| Actually runnable in `app-runtime.js` | **64** |

**The signature story is fake.** `privacyfold-agent-surface.md` §8 makes a signed registry the trust anchor for feeding instructions into other people's agents. What exists:

- `public/schemas/_index.json.sig` — a hand-typed constant `7f8e9a0b1c2d3e4f…`, and the index's actual sha256 is `7ccdb672…`.
- `packages/mcp-server/index.mjs:14` — `PINNED_ED25519_PUBKEY = 'MCowBQYDK2VwAyEA8f9a2b3c4d5e6f7a8…'` (a made-up literal, visibly sequential hex).
- `whats-new` returns `signature_verified: true` **unconditionally**; there is no verification code in the file.

`@privacyfold/mcp` is also unpublished, has no README/LICENSE, and reports version `1.0.0` while claiming `registry_version 1.4.0`.

For a privacy product whose moat is "trusted, current, machine-readable requirements", a supply-chain surface that lies about verification is worse than having none.

## 6. Legal, ads, and the privacy story

Missing entirely (verified by file existence): **privacy policy, terms of service, cookie notice, about, contact, `ads.txt`, `security.txt`, favicon, custom 404, `.gitignore`, `LICENSE`, `SECURITY.md`.**

- `content/config/site.json` sets `adsense.enabled: true`. `src/components/AdSenseUnit.tsx` renders a **static fake ad card** ("Privacy-First Developer & Document Hardware", `slot=pf-… · npa=1`) with no `ca-pub`, no `adsbygoogle.js`, no consent. AdSense review rejects this (and "no ads.txt" alone stalls monetisation).
- `public/_headers` sets `connect-src 'self'`, which would **block AdSense** the moment it were real. The CSP and the revenue model contradict each other.
- The app's only third-party request is **Google Fonts** (`fonts.googleapis.com`), verified via `performance.getEntriesByType('resource')` on the live page. A zero-upload privacy brand sending every visitor's IP to Google on every page is both a GDPR exposure and a credibility hole; the CSP explicitly whitelists it.
- `ToolSeoArticle` and the JSON-LD both claim *"Works offline (PWA Service Worker)"*. There is **no `sw.js`**.
- `manifest.webmanifest` has no icons; a PWA install prompt will fail.
- No i18n of any kind, while `docs/privacyfold-growth-strategy.md` promises 25 locales and localized slugs.

## 7. SEO integrity risk

167 sitemap URLs would be emitted (1 home + 1 blog index + 72 tools + 87 presets + 6 posts), all pointing at pages that either fail to build or (in the standalone artifact) describe capabilities that don't exist. Structured data asserting `SoftwareApplication`, `HowTo`, and *"0 Bytes uploaded (Verified per run)"* for tools that are stubs is the kind of thing that earns a manual action rather than a ranking.

No `og:image`, no `twitter:card`, no per-locale canonicals, no `hreflang`. Canonical host is hardcoded to `https://privacyfold.com` in five files (fine, but undocumented as a convention).

## 8. Process: the foundation is the weakest part

At audit start:

- `git status` → **not a repository**. A `.git` appeared at 18:25 with `origin = github.com/dev-electro/privacyfold`, **0 commits**, and `origin/main` containing only 10 files (docs + reference UI). **All 388 product files existed nowhere but this working tree.**
- No lockfile (`package-lock.json` absent) → `npm install` is non-reproducible.
- No CI (`.github/workflows` absent), no deploy config (`wrangler.toml`/`netlify.toml`/`vercel.json` absent) despite the infrastructure doc specifying Cloudflare Pages.
- No tests: `public/tests/us-passport-std/vectors.json` is data with no runner. Zero unit, zero e2e.
- No monitoring, no error boundary, no analytics, no uptime checks, no backup of `dist/index.html`.
- README describes Astro + Tailwind v4; the code is Next 15 + Tailwind 3. Docs and code have diverged in three places (tools count, presets count, framework).

---

## 9. What is actually good (don't throw it away)

- **The design is the asset.** The origami desk metaphor, family system, paper/ink tokens, mobile drawer, and typography are coherent and distinctive. `reference-ui.html` is a better spec than any of the markdown docs.
- **The honest tools are genuinely useful** and correctly client-side: passport photo, image compress, EXIF strip, hash, base64, JWT, JSON, regex, diff, unit, cron, QR, password.
- **The content system is the right architecture** — Git-tracked JSON per tool/preset, validated before build, 87 presets with `version/status/last_verified/stale_after_days/source_url` all populated. That is a real moat if the pages are honest.
- **The agent-surface *design* (`privacyfold-agent-surface.md`) is strong**: two lanes, fragment-only payloads, freshness fields, conformance vectors. It needs implementation, not rethinking.

## 10. The gate: what must be true before this goes public

**P0 — cannot launch without these (blockers)**

1. **Version control.** Commit the tree. Add `.gitignore` (`node_modules`, `.next`, `.DS_Store`), commit `package-lock.json`, push to `origin/main`. *Today's exposure: one `rm -rf` from zero.*
2. **Make the build honest — pick one artifact.** Either (a) delete the Next app and ship `dist/index.html` behind a documented `scripts/build.mjs` that regenerates it, or (b) do the real port: migrate 72 tool JSONs to the `GitCmsTool` schema, add `seo.steps`, delete `src/app/tools/[slug]`, and move the desk markup into React. (b) is 2–4 days; (a) is 1 day. Ship (a) now, do (b) with margin.
3. **Remove or implement every fabricating tool.** `pdf_compress`, `ocr_scan`, `voice_transcribe`, `chat_pdf`, `ai_writer`, `bg_remove` must either do real work or be marked `coming soon` and stripped from `llms.txt`, `.well-known/mcp.json`, `_index.json`, schemas, and JSON-LD. Fabricated names/amounts in a tax tool is a liability, not a bug.
4. **Make the 8 unimplemented tools invisible** to SEO and agents until they run. No page, no schema, no registry entry.
5. **Kill the WASM fiction.** Either ship the binaries or remove `/wasm/...` from every surface (llms.txt, schemas, JSON-LD, SEO copy, SRI file). Pick per tool; don't blanket-claim.
6. **Legal minimum:** privacy policy (what is processed locally, what third parties see), terms, contact page, cookie/consent statement, `ads.txt`. Even with 0 uploads, analytics/ads/fonts need disclosure.
7. **Self-host the fonts** and drop `fonts.googleapis.com` from the CSP. This is the cheapest credibility win available.
8. **Fix the agent trust story:** delete the fake `.sig` and pinned key, or implement real Ed25519 signing + verification. Never return `signature_verified: true` without verifying.
9. **One canonical tool count** across `layout.tsx`, `site.json`, `llms.txt`, `_index.json`, `.well-known/mcp.json`, and the MCP server, generated from `content/tools`.
10. **A smoke test in CI** that proves each advertised tool produces its advertised output type, and fails the build on drift.

**P1 — before paid traffic / AdSense submission**

11. Real AdSense integration behind a consent gate, or remove `adsense.enabled` and the fake ad card.
12. Service worker + icons + offline page, or delete the offline claim everywhere.
13. `og:image`, `twitter:card`, favicon, 404, `robots.txt` review, `hreflang` plan.
14. Error boundary + a minimal, cookieless analytics event for `tool_used` (no file data, no URL params).
15. Name/number QA pass on the 87 presets against their `source_url` (they carry `last_verified` — honour it or drop it).

**P2 — growth foundation**

16. i18n scaffolding (even if only EN ships).
17. Conformance vectors per preset with a runner (`vectors.json` → `node scripts/vectors.mjs`).
18. MCP package published, versioned, with README + LICENSE.
19. `LICENSE` for code and CC-BY-4.0 for `content/presets` + `public/changelog` (the agent doc already commits to this).
20. Deploy config + rollback (Cloudflare Pages project, preview branch, `wrangler.toml` or dashboard-documented).

---

## 11. Bottom line

The **front of the house is finished** — design, IA, copy, the content pipeline. The **back of the house is a stage set**: the build does not compile, the Next routes render an empty div, there are no WASM binaries behind 72 WASM claims, six live tools invent the user's data, and the agent registry signs itself with a made-up key.

Shipping this as-is would convert a credible privacy brand into a "fake tool" site within one Trustpilot review and one Reddit thread. The good news is that the failures are **known, bounded, and mostly deletions** — removing claims is faster than building features, and the honest half of the catalog already works.

**Recommended sequence:** P0 #1 (commit, today) → #3/#4/#5 (de-hype the catalog, 1–2 days) → #2a (ship the standalone artifact properly, 1 day) → #6/#7/#8/#9/#10 (1–2 days) → public soft launch → then the real Next port with margin instead of a deadline.
